# 阶段 B · 离线语义编译器

输入一张有类型的语义图，编译器按依赖顺序选择义项、绑定主体、组织过程，并返回完整的 Magic Core、逐节点 Trace、词项证据及下游转译结果。当前实现覆盖单一空间主体；这个主体可以有多个关系、过程和互斥的事件分支。活动 Core 为 0.1.2，词义规则为 0.1.1，构造规则为 0.1.1，执行格式为 0.2.2。[编译入口](../../tools/magic_compiler/compiler.py) · [构造规则](../../game/data/core/construction.json)

## 运行

在仓库根目录执行。命令需要 Python 3.10 或以上，依赖文件固定了 Draft 2020-12 校验库的版本。

```sh
uv run --isolated --with-requirements tools/magic_compiler/requirements.txt python -m tools.magic_compiler compile game/data/tests/semantic/heldout_strand.json
uv run --isolated --with-requirements tools/magic_compiler/requirements.txt python -m unittest discover -s tests -v
```

`compile` 读取裸图数组，或含 `versions`、`graph` 的输入包。裸图使用仓内活动版本；输入包可同时锁定输出记录的构造版本。读取参考案例时只传入图。例如，从现有引力构筑生成向上变体可执行以下命令。

```sh
jq '.[] | select(.id=="L05") | .graph | .[2].intents[0].direction.axis="up"' game/data/examples/law_core_cases.json |
  uv run --isolated --with-requirements tools/magic_compiler/requirements.txt python -m tools.magic_compiler compile -
```

标准输出为 JSON。词义不成立、多个解释、悬空引用、回路、未覆盖的词、版本不符都有定位信息；非法输入返回非零退出码。语义成立后若执行能力或预算未通过，仍返回 Core 和 Trace，并在 `execution.status` 给出原因。规则匹配仅消费图的结构化字段。案例名、说明文字和人工预期由测试端使用。

## 已覆盖的层次

- **词项。** 25 词、33 义均有实际匹配。每项记录对象所需事实、来源、授予与排除的能力、留待现场核对的条件。比如缺少「已有推进」时穿透匹配失败；火的两种性质都可抽离却未指明时，返回显明与温热两个候选。
- **整体构筑。** 13 个参考输入有 11 个自动生成完整 Core 和 Trace。参考回归对齐对象身份，逐项比较来源、空间、关系端点、操作、触发、前置过程、条件、效果、供给、词义及每个 Trace 步骤指向的产物。说明文字由编译器生成。M017 和 M020 在「封存」词项返回 `UNSUPPORTED_MEANING`。
- **执行。** 四个独立显明、抑光、温热、抽热构筑（L01–L04）可直接导出并离线准入完整的 `execution.compiled_spell`。其余七个通过的参考构筑输出 `GUARDED_PLAN`，列出过程、依赖、现场条件、通过 Schema 的操作、能力与已知成本。引力的冲量在松手时需要读取实际余额，0.2.2 的冲量幅值是字面数。水网仍需把持续束缚及分支撤除完整绑定到执行句柄。消费者应检查 `status`、`remaining_bindings` 和 `budget.all_operations_priced`。离线探针只消费当前验收所需的操作和现场数据。
- **回归。** 7 份旧执行基准及 1 份旧意图通过离线检查。21 条旧工程反例逐条实际施加修改，全部在预期阶段被拒绝。旧文件保留原文，具体修改单独登记。语义向量中，结构振动感应 S16、场所储备耗尽 S20、器物预付照明 S21 仍待相应语义或执行绑定。部分向量已在词项、权限或现场条件层验证，尚未晋级为整术执行。[工程反例修改](../../game/data/tests/execution_mutations.json) · [离线准入](../../tools/magic_compiler/admission.py)

M009 在输入图中明确写入持续控制、相变储备和冻后维持的供给。M001 写入推进储备，M015 写入信息联结的维持供给。这些补项使原参考 Core 中已经存在的费用能够从输入推导。预算与时间数值使用本轮离线标尺，实机性能和美术效果另行验收。[参考输入](../../game/data/examples/water_core_cases.json) · [离线数值](../../game/data/balance/offline_profile.json)

## 研究 02 回归 · 以太七公理

| 离线回归 | 已观察结果 |
|---|---|
| 引力蓄积与松手 | 向上、向下共用局部引力许可。目标是 `load` 的实际作用，范围是 `v1`，供给来自施法者预付的 `@reserve`。方向反转只改变两个轴；目标出域、余额为零或提前打断均交付零。 |
| 水网原位相变 | 同一份产物在完好水网上冻结 5 段，断边后冻结 3 段，几何接触没有跨边传播。借水同时要求来源可达、有水及施法投入；松手相变须有原材料与储备；冻后主动约束另需接触和持续供给。 |
| 声明、权限与旧版本 | 等价的显式声明和编译器推导产生相同结果。删除世界许可、缺少词义、伪造来源或扩大作用域都会失败。13 个旧参考输入可按 Core 0.1.1、构造 0.1.0 回放，11 个产出 Core，2 个仍在封存词项给出原诊断。单股水线按 0.1.2 编译。 |

引力与水网的执行状态均为 `GUARDED_PLAN`。水网探针使用给定的液态材料、布尔储备和现场连边；它没有测量每段相变的能耗。引力探针核对一个局部作用的有限交付，没有测量两个法术叠加的世界结果。跨实例只验证了五种可引用方面的结构和拒绝边界。寄托储备耗尽、外部供能断联、多术抵消与过载、失去支撑后的刚体运动仍需执行验证。[新增回归](../../tests/test_aether_interventions.py) · [声明向量](../../game/data/tests/semantic/aether_interventions.json)

## 交回语义讨论的问题

1. **蓄积的作用归谁。** 已确认松手最多交付实际积下的部分，中断终止尚未交付的作用。中断或目标出域时，已付出的那部分应消散、返还，还是能转移到另一个明确的储备主体？这会改变资源契约；每秒积多少可以留给平衡配置。
2. **水网束缚的责任如何交接。** 目前 M009 实现了“先冻结，再以额外供给维持接触约束”这一分支。单靠冰形与现场支点可留存的自然约束，和玩家续费的主动束缚，应如何在同一门语言中分别指定起止与承担者？见决定 D14。
3. **寄托后的载荷、能量与触发权。** M017 和 M020 都在「封存」处遇到边界。先确定被寄托的是材料、已授权的作用还是可支用的余额，再确定谁能触发、耗尽或损毁时哪一部分留下。这个答案决定「封存／释放」进入构造器后的所有权规则。[设计决定](../../game/data/core/decisions.json)
