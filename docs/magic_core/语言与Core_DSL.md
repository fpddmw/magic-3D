# 语义语言与 Magic Core DSL

## 词义与解释

[词义表](../../game/data/core/meanings.json)按稳定义项 ID 登记玩家熟悉的词。每项给出对象类型、需要的前提、引入的结果、保留项、排除的推论和中文解释。同一字面词可对应多个义项，例如「联结」可以传力、取源、回传感应或寄托作用。选择依据是端点是什么、哪种内容可通行、关系怎样维持。词条中出现的条件是解释约束。来源是否实际有水、载体是否仍完整，要到施法时绑定。

同一对象上，「凝聚」建立有限内部结合的要求，「延展」要求沿参照连续伸长。求取同时满足两项限制的组织，再结合材料、实际来源与契约。若约束互斥，返回冲突的节点。若「火＋以太＋分离」可以抽取显明或温热，则返回候选义项及需要补选的性质。解释器仅匹配已登记的类型、约束、关系和变换。案例 ID 只供追溯。

凝聚与汇聚分属整体结合和运动趋向；弥散与扩散分属分布状态和分布变化；铺展与延展分别说明覆盖面和连续伸展。环绕取中心参照、包覆贴边界、包围规定内外。封存限制对外发挥，潜伏保留能力的休止状态，释放解除限制，唤醒启动既有能力，爆发集中交付已有作用。时间上的积蓄要求有时间、供给、储备对象和交付条件，是否单列符文见 D13。

## 从语义图到 Core

[六条构造规则](../../game/data/core/composition_rules.json)登记各形式的合并方式、继承和拒绝条件。每个 Trace 步骤同时引用一条构造规则和具体义项。

| 构造关系 | 含义 | 可以检查的结果 |
|---|---|---|
| 共同限定 | 若干词约束同一个对象或作用 | 两词都对最终组织有贡献 |
| 修饰 | 指明某个性质、端点、过程或局部 | 反转温热只改变热通道 |
| 构成 | 在概念层形成结果 | 法坛推得冰不会在玩家脚下冻结一滩水 |
| 接续 | 让实际事件成为后续变化的前提 | 松手之前发生的打断进入独立的退场分支 |
| 阶段 | 绑定形成、维持、交付或中断 | 当期责任与供给可查 |
| 共享引用 | 引用既有知识、主体、性质或关系 | 引用同一水网不会再生成等量的水 |

以霜网为例，构筑先指明「水」和「借用」，再用延展和交织共同限定同一水体。主动收束引用此刻已成的那张网；打断发生时只撤去主动支撑。冰带原本接触敌人的位置可继续构成自然约束，额外加强束缚需要另一份持续供给。图鉴分支与旧执行基准的差异见 M009 的 lowering 字段。[完整数据](../../game/data/examples/water_core_cases.json)

## 首批义项的判定依据

首批 24 词和为水网增补的「汇聚」使用封闭的 `match` 条目。对象类型限定候选，`all` 是必须同时满足的事实，`grant` 是本词项准许后续引用的事实。`retain` 标记须继承的性质，`exclude` 列明该词不能单独授权的推论。`at_use` 是施法时用对应世界数据核实的条件。其余词条仍供设计者审阅。比如「爆发」需要已有可交付作用，储备槽本身只提供容量；选择持续积蓄并有供给后，契约才允许「延续」的结果向下游提供可交付作用。[词义判定来源](../../game/data/core/matching_basis.json)

词、操作数和局部选择分别保存在 `words`、`operands`、`intents`。现场材料、余额或连接状态在构筑阶段只登记待绑定条件。例如相变词项的 `solidified` 授权原位转固，实际冻结段由现场材料和传播前沿决定。指向上游的 `n3:1` 指 n3 节点的第二个词项，`v1` 等仅标记本次构筑的主体或过程。词义先取证，空间和过程选择再用该节点读到或推得的事实取得许可。一次选择可以固定世界方向或施法事件；材料传播仍须引用同一份材料的实时连接。[逐步复核与反例](阶段A_配对验收.md)

## 数据契约

仓库使用一个 Draft 2020-12 [Schema](../../game/data/schema/magic_core.schema.json)，其中 SemanticGraph、MagicCore、CompileTrace 和 Lowering 各有独立定义，可按 JSON Pointer 引用。一个案例保留版本、输入图、预期 Core、逐步推导及下游对应关系。

| Core 声明 | 身份与引用 | 意义 |
|---|---|---|
| concepts | 本地 ID 与概念目录项 | 本次具有何种本性，可引用哪一方面 |
| subjects | 本地 ID、概念引用、来源和绑定要求 | Manifest 用魔力具现，Borrow 借实际来源，Reference 取得现场对象，Transform 承接已有主体 |
| relations | 两个端点、作用通道和有效条件 | 支撑、输水、馈能和感应各核对实际可传内容 |
| processes | 操作、目标、触发时机、依赖、前提、结果 | 接触、收束、打断与耗尽对应实际变化；七类变化只用于描述已确定的作用 |
| contract | 形成、控制、供给、归属、释放与中断 | 即时投入、持续供给和预付储备可以按阶段交接 |

图节点的 inputs 引用已成立的语义节点，scope 说明词的作用范围，aspect_ref 可指向登记的具体性质。Trace 将每个节点的词依次落实到义项和 Core 局部 ID。下游有旧基准时，另列经核对的执行 ID 及尚未覆盖的义项。图的先后表示语义依赖；只有 Core 过程的 when、after 和有效条件决定世界中的先后。after 表示前置事实已成立，持续塑形可以已有部分产出。多个互斥的输入事件可以共享同一前提。阶段 B 编译器须检查唯一 ID、引用、冲突、时序、资源与权限。当前条件和结果的中文叙述用于人工审阅与测试预期，不能作为脚本执行。

每个主体的 source_ref 明示来源或费用承担端。过程的 requires_all 和 effects 使用世界登记表中的封闭事实词汇，分别列出同时成立的前提和允许提交的变化。事件及依赖规定何时检查。比如 M009 的 freeze 需要主动释放、实际材料和储备可用，产出原位转固；打断分支只撤去主动作用。条件中的「供给终止」指契约所需的任意来源或储备失效。细分阈值由下游平衡规则提供。

空间组织归属于主体、性质与关系。参照可在成形时捕获、持续跟随、附着局部坐标或由玩家引导。期望分布与实际轮廓分别记录，材料空间、实际作用范围和艺术空间分别消费。来源、目标和支点在施法时解析。缺材料时按契约中止或交付已成部分。共享符文知识允许多个引用，两个实际作用则分别检查支撑、消耗和控制。瞬发、维持、吟唱与仪式是这些维度上的常见组织，允许「吟唱形成 → 器物封存 → 预付 → 受压回应 → 释放」的责任交接。


## 逐过程干预契约 · Core 0.1.2

每个过程有一项 `intervention`。构筑者可以在已有过程选择的 `intents[].intervention` 中明确限定 `mode`、`target`、`permission`、`scope` 或 `responsibility`。省略的内容由构造规则推得，写出的内容须与可证明的解释一致。下例可加入引力的松手选择；把空间参照换成未绑定的 `v9` 会被拒绝。完整的两组声明随回归向量保存。[引力和水网声明](../../game/data/tests/semantic/aether_interventions.json)

```json
{
  "mode": "干涉",
  "target": {"kind": "relation", "ref": "load", "facet": "effect"},
  "permission": "gravity.local_acceleration",
  "scope": {"kind": "in_region", "ref": "v1"}
}
```

| 编译后的字段 | 从哪里来 | 何时生效 |
|---|---|---|
| `mode`、`target` | 世界许可给出干预方式与可改变的方面，构筑绑定具体主体、关系或本次储备。 | 引力作用于域内受力关系的加速度；停止冻后束缚则只指向已建立的束缚关系。 |
| `basis.permission`、`basis.terms`、`basis.medium` | 查世界许可，核对依赖链上词项授予的事实，记录词项地址及隐含或显式媒介。 | 法坛能复核每一步的解释。删除许可或缺少词义依据会分别报错。 |
| `scope`、`basis.site_conditions` | 绑定本次空间、来源、关系端点、实际接触或连通材料。保留原过程的方向、传播起点和采样方式。 | 引力读取当前域内观察。相变沿同一材料从当前支点出发，前沿逐步读取活边。 |
| `responsibility` | 记录供给来源、即时／持续／预付时序及余额、控制等要求。预付标明本次储备；依赖已交付作用或结束支撑时标明前置过程。 | 现场同时满足 `site_conditions` 和责任的 `conditions` 后才可交付。两组条件合起来就是过程的 `requires_all`。 |
| `responsibility.on_end` | 本轮统一保留已经发生的世界变化。 | 停止主动束缚时撤去该关系；冰在后续如何运动取决于实际支点和受力。 |

以太通道的建立和撤除可以追到显式以太词项。普通借水、凝固和有限引力使用隐含媒介。`SupplySource` 可声明施法者、带储备引用的器物或场所、带连接引用的外部来源。后两类还需要相应的建立和支取规则。跨法术目标使用 `active_magic`、实例槽、成员引用和实际方面；阶段 B 能检查这种声明，遇到跨实例绑定会返回诊断。

世界许可及词义前提登记在世界表，过程与许可、供给的对应登记在构造表。下游计划逐项保留干预，`spatial_bindings` 将法坛空间引用对应到执行空间。数值量级由平衡配置提供。[世界许可](../../game/data/core/world.json) · [构造规则](../../game/data/core/construction.json) · [Core Schema](../../game/data/schema/magic_core.schema.json)
