## 0. 本次校准：为什么需要改路线

项目的核心不是制作一组漂亮的法术再把它们参数化，也不是建立一门严谨的物理配置语言后附加视觉轨道。核心是：**玩家以少量多义符文表达意向，模型运用世界知识、魔法构思知识与艺术知识，编排出有独立意象、真实世界作用、自然操控及完整艺术演出的确定性魔法。** 它能够进入同一个世界，与普通对象及其他魔法继续发生关系。

DSL 本身包含我们对存在、性质、作用、空间组织、控制、节奏、形态与美学的理解。技术美术和 DSL 不是两条先后完工的路线。每次高价值魔法创作都是一次对这门语言、知识与运行技术的联合研究。

审阅基线的 `AGENTS.md`、`README.md`、`docs/v0.3/演进与切片计划.md`、`docs/art_research/技术美术实验室与升级计划.md` 都有「Stage 0–2 暂冻 DSL，先做艺术样本与算子，Stage 3 一次性反哺」的要求。此旧顺序已撤销。旧计划 T1–T5 中有价值的技术选型、资产管线与质量否决项保留，但不再作为脱离魔法设计的独立施工顺序。

当前首版天体研究已经说明：执行了高分段球面、月面纹理、解析光学厚度、曲带扫掠、GPU 微粒、骨骼与音轨等要求，并不等于完成了优秀魔法。球体、光带、角色和动作都可以分别成立，整个现象仍然不成立。当前首版以固定时间播放、独立运动及扫掠碰地结束，尚无引力、抽热、光学消光或奥术干涉的真实世界作用；其艺术定位也未得到认可。不得将其计为优秀魔法、可编译法术或已验证的通用艺术算子。保留为技术研究与失败案例。

### 0.1 对研发 Agent 的最高层指令

- 从**值得创造的魔法**出发：既有明确的核心意向，又有自身艺术生命力和跨场景用途。不得从待测函数反向拼装所谓原创魔法。
- 先明确意向、机制、交互及整体艺术构成，写出候选配方和技术承接关系；艺术与实际机制相互启发，允许反复修订，不实行僵硬的单向流水线。
- 同一轮研究必须产出配方、编译知识、可复用技术和真实观测。不得用完成一个 `.gd`、一张效果图、一个测试或一份文档代替整轮交付。
- 若实现无法兑现设计，记录是哪一层不足，局部迭代。不得悄悄缩减现象、改变符文意向，或把缺失能力偷偷替换成更简单的表现。
- 不以固定术名、案例号、测试场景名或符文组合分派完整法术逻辑。可制作有艺术完成度的局部资产及高级构造器，但其依赖、参数、责任与展开语义必须明确。
- 不承诺全量模拟或无限程序化艺术；采用有界、可解释、具有艺术质量的近似。高质量与可扩展性是并列目标，不能为其中之一牺牲另一项。

## 2. 新研发架构：两条闭环，六个互相约束的层次

### 2.1 研究闭环（研发时）

```
自然魔法意向与整体艺术构思
       ↕
现象 / 交互 / 编排的候选 DSL 与编译知识
       ↕
Godot 技术映射、资产与局部真实世界后端
       ↕
真实体验及独立读谱评议
       ↕
修订语言、知识、能力契约；陌生构筑迁移
```

这不是固定的五个施工阶段。设计会受到技术研究启发，技术研究也会因配方表达或审美缺口改变。任何一层不能连续数轮独立推进。局部光学、网格或声音实验允许短期独立存在，但必须标明它服务于什么现象、将对应什么能力、怎样接回配方；实验本身不是完整魔法。

### 2.2 玩家构筑与运行闭环（产品设计）

```
RuneGraph + CastingContext + PlayerKnowledge + 可选局部锚
  + 世界/DSL/能力/艺术版本 + 编译所需的相关创作知识
      ↓ 高能力模型构思（法坛；非战斗实时）
解释 + RuneContributions + 完整六面配方 + 可选因果改锚
      ↓ 确定性展开、类型/权限/锚检查、报价、能力匹配、读解
已确认的版本化 Recipe / WorldPlan / StagePlan
      ↓ 普通输入与世界快照、事件
WorldLaw / Jolt    ←共享实际状态与回执→    ArtKit / Director
      ↓
真实世界后果、完整演出、玩家体验
```

模型选择的艺术参数、局部片段及资产依赖也属于保存的配方。运行时不让模型重新解释或补全。世界行为由确定性计划驱动；视觉按约定的时钟和状态运行，可有固定种子与质量档变化，不要求不同硬件逐像素或 Jolt 浮点轨迹完全相同。模型不得自报实际消耗。

### 2.3 不要混淆六个层次

| 层次 | 内容与所有者 | 例子 |
|---|---|---|
| 意向与锚 | 玩家明确的需求，模型负责提出自然解释 | 聚拢周围实物；不是必然生成实体球 |
| 世界语义 | DSL Concepts/Subjects/Relations/Processes/Contracts | 局部重力域、有限作用、谁负责供给、断供如何结束 |
| 艺术构造语义 | DSL Expression 中可组合的整体构图、形态、时空演化与导演 | 外围向内凝聚、局部负空间、前后层次、真实作用后承接余韵 |
| 创作知识 | 模型上下文；设计原则、适用条件、建议、禁例及选择依据 | 向心力量不自动意味着旋转；宏大不等于全屏强光 |
| 能力契约与确定性映射 | 版本化注册表、解析器、参数约束、状态输入输出 | 有界向量场、弧长扫掠、局部相位映射、事件绑定 |
| 技术与资产 | Godot 后端、网格、Shader、粒子、动作、声音与降档 | 预分配网格、Jolt 查询、PBR 材质、GPU 粒子 |

艺术指导不是世界公理；资产名称不是魔法语义；技术算法不是玩家必须学习的符文。世界作用和艺术作用可共享结构描述，但具有不同权限。同一性质有不同艺术解释，同一视觉形象可承载不同真实机制。

## 3. 每轮联合研究的标准工作单元

一次研究围绕一种有普遍价值的魔法构成思想，而非一个 Shader 或一个完整法术母版。允许研究多个相近意象，以避免单个样本把抽象引向错误方向。优先完成当前核心问题，局部探索可并行，不要求一项效果达到发布级才允许研究下一种美学。

| 步骤 | 必须实际做的事 | 必须留下的结果 |
|---|---|---|
| U0 设计命题 | 从少量符文或自然意向提出完整现象；列出核心预期、可选解释、不可偷加效果，说明通用用途 | `intent.md` + 机器可读输入/锚/排除项 |
| U1 联合设计 | 写实际成立依据、可操控输入、空间及时间组织；做整体意象图、关键分镜、形变及音画关系；同一现象在普通场景中的体验 | `design.md` + 分镜/构形图 + 预期因果表 |
| U2 配方与技术映射 | 用现行 DSL 候选写出完整六面，包括 Expression；补足确有需要的构造语义；逐项映射到状态、算法、资产与能力签名 | `recipe`、`mapping.md`、语言/能力差分、未支持清单 |
| U3 实机联合实现 | 用同一份可加载编排数据驱动现象和演出；接入必要的真实作用、输入及终止，不要求全项目引擎改造 | ArtLab 可交互实例、确定性编排载入、局部后端、原始观测 |
| U4 评议与修订 | 看连续视听、普通第三人称视角、动态承接、变化是否读得懂；独立读谱；定位真正的失败层 | `review.md`、前后对照、具体缺陷及决定 |
| U5 知识与迁移 | 从通过/失败的构思和技术中提炼可复用规律；尝试同配方换场景与不同意象换编排 | `knowledge`、迁移配方、复用范围、证据及下一轮问题 |

### 3.1 设计先行的含义

开始编码前，至少能回答：玩家原本想要什么？什么真实存在？什么只是艺术？什么能改变？操作承诺与失败是什么？宏观形象如何在时间里成立？什么东西会留在世界？为何这样构图而非别的构图？技术无法实现时有哪些等效艺术方法？

重要美学/世界权限选择由负责人确认（优先给出两三种有实质差异的方向与推荐理由）。确认的对象是完整构思，而非某个几何体。局部技术研究可以同步进行，但不得把未确认的候选作为正式设计。不能因为实现便利而先定球、环、颜色、固定四拍。

### 3.2 每个样本必须是自然的玩家魔法

先定义独立能力，再在三个不同现场观察用途。例：驾驭局部水体是魔法；用它给两只杯子倒水是某个机制观察；不可反向把杯子、石扣、绞轮写成该魔法默认所需的端口。特殊现场允许存在，但若是明确锚定的构筑条件，应在法坛可读，而不是隐藏前提。

原创设计应满足：意向自然、形象鲜明、作用诚实、操控适合第三人称、能够迁移、演出整体统一。审美目标是庄严、优雅、重量、神秘、留白与力量感，不等于所有魔法都巨大、缓慢、发光或有爆炸。小型感知或关系魔法也可成为优秀样本。

## 4. DSL 与艺术编排的共同深化：重点是什么

保留 A–D 中已有的空间几何、关系、过程、端口、作用域、状态绑定和展开规则。当前优先不是扩大词表，而是让复杂形象从静态排布发展为连续的构成语言。每项新增候选应同时回答世界语义、艺术语义、解析与技术映射；纯表现能力无需硬凑物理作用。

### 4.1 动态构形是第一优先，而不是静态模型库

区分几何目标、真实形体、艺术形体。为连续结构保留局部参数域（路径弧长 s、曲面坐标 u/v、体域归一坐标、阵元稳定键），描述骨架、截面、局部坐标帧、局部厚度和分布。构形可以被组合、变换和部分引用，不要求底层暴露任意代码。

重点补足：

| 构成规律 | 需要可表达的语义 | 技术承接候选 |
|---|---|---|
| 连续形变 | 根部与末端分别怎样跟随、展开、扭转、弯曲，局部幅度与速度如何不同 | 少量控制点 + 曲线插值 + 平行传输帧 + 固定拓扑扫掠 |
| 构图承接 | 起始构图与目标构图的对应关系；过渡期间如何保持整体剪影与局部身份 | 稳定参数域、关键构形、中间构形插值；不要求任意网格 Morph |
| 局部拓扑变化 | 明确分裂、断开、汇合、重排的实际触发和局部承接；不凭插值生成新材料 | 稳定子键、切分/合并记录、有限拓扑重建、局部状态转移 |
| 形态与物质共演化 | 结构拉长、压缩或变宽时如何分配有限内容；物理占位和作用前沿何时成立 | 截面体积/容量约束、显式补料/排出/停止策略、近似离散材料单元 |
| 异质复合 | 多主体共享构图但各自有性质、空间、运动、责任；叠加域如何去重或分别交付 | 局部 frame / fragment、按通道签名与独立责任结算 |

所有新构形规则须区分 `visual` 可任意艺术变形与 `realized` 受材料、碰撞、控制约束。复制几何描述不复制质量或储备。共享视图、共享引用与新实例不得混用。

### 4.2 空间相位与时序必须结合

不只给轨道设置一个整体 progress。允许一个连续变化由局部位置、真实前沿或事件产生延迟、传播与错相。通用概念为局部参数 p(s,t)=clamp((t−τ(s))/D,0,1)，其中 D 是局部变化时长。τ 可由弧长、有限拓扑距离、真实成形前沿、阵元索引或合法状态派生；不是每次新增专属传播函数。

实际相变、连通、作用前沿由世界提交，不允许 Shader 的相位反向产生真实冻结或命中。纯艺术前沿可有独立速率和曲线。输入不可预知时，不能用最大蓄力时限倒推实际松手。支持真实打断、提前释放、延迟和交接时的取消、锁存、衰减。形态承接应保存局部参数、纹理相位、必要的位姿/速度历史；允许合理交叉淡变，但不得用它冒充真实结构变形或材料继承。

### 4.3 整体美学不是多个轨道加权相加

C-stage 中的视觉、环境、声音、身体、镜头分轨及 hero/secondary 仲裁有价值，但不能代替艺术构图。

候选 Expression 应能组织：主剪影和局部比例；空间疏密、留白与有意的不对称；多尺度材质；共同运动秩序与局部差异；明暗和色彩层次；一段完整的张力变化；身体与环境在不同阶段承担的表现。角色、核心、环境不必始终各有一条显著特效。

`composition`、`deformation`、`phase_profile`、`motion_binding` 等是研究用概念名，**不是强制新增顶层字段**。先尝试用 A7 与 C5 的组、局部参照、事件、参数驱动表达；确实不足，再统一语义。高层艺术约束可以指导构思或参数归一，但不能留一个 `epic=true` 让引擎凭空创作。已经确认的配方必须将艺术选择落到可解析的形象、参数、资源、时间和依赖。

### 4.4 共用与独立的边界

- 同一世界作用可用沉重、锋锐、空灵等截然不同的艺术编排。外观变化不得暗改伤害、作用域、控制或消耗。
- 同一艺术构图可承载不同世界作用，但必须保留不同作用的可读性：如能承载与仅遮光须有区分；装饰不能假装安全面、伤害面或感知结果。
- 形态/材质/运动的适配条件应进能力契约；不要将一张材质名表与所有载体强行笛卡尔积。静态场合可以使用简单高质量几何，合理的简洁不是占位。
- 资产级复用允许高质量局部资源、专用渲染机制、动画片段与声音组。禁止以完整法术名触发闭合演出逻辑；作者可选择并自由组织局部艺术组。

## 5. 编译准备：把设计理解转化成可复用的知识与能力合同

这是每轮必做的设计交付，不是最后训练模型时才补的提示词。语言本身给出可确定性解释的机制；创作知识告诉模型如何做出自然、有价值、具有美学完整性的选择；能力注册表告诉模型哪些选择在当前版本真的可以兑现。

### 5.1 四类知识与记载方法

| 类型 | 每条应包含 | 例子 |
|---|---|---|
| 世界/性质知识 | 适用本性与状态、媒介、权限、代价、实际条件、反例 | 重力作用于质量体；改变重力不是凭空变出物质、热量或消光 |
| 魔法构思知识 | 自然意向、可选机制、核心与补全、操控、适用范围、相邻意向的区分 | 「聚」可聚物、聚场、聚能；与重力共同组织时，向心牵引是一种自然解释，但非唯一 |
| 艺术构成知识 | 想表达的气质、可选构图与运动原则、作用的可读线索、审美失败反例、可迁移场景 | 向心力可由外围对象偏移、负空间、密度收紧表达；不强制紫球或旋转环 |
| 技术能力知识 | 输入/输出类型与单位、实际状态/艺术状态、可组合条件、资源成本、支持状态、质量档、局限 | 曲线扫掠可变截面、局部相位与稳定参数域；若拓扑改变必须有接续合同 |

每条知识注明 `id/version/scope/status/provenance`，明确是公理、设计原则、创作建议还是已验证能力，保留失败例及替代路径。知识不能是隐藏的「某符文串 → 某技能」查表。不要把整个语料无差别塞进提示词；按本次图、锚、玩家已知词与已支持能力提供相关知识与可用签名。正式训练推迟到稳定机器契约与有评议的记录出现之后。

### 5.2 最小能力契约（示意，字段需与已有设计统一）

```
capability: sweep_geometry
version: candidate.1
inputs: curve_frame[], section_profile, twist_profile, local_phase
reads: desired/realized/visual domain; stable sample keys
outputs: geometry samples, actual or visual bounds, local coordinates
invariants: bounded count; explicit frame; no material creation
backend: CPU curve/frame samples + GPU/ArrayMesh sweep
combinations: phase_profile, thickness_profile, material_adapter
limits: degenerate tangent, self-intersection, sharp junction; explicit fallback
quality: hero / standard / distant (preserve required contour)
status: prototype | verified_backend | admitted
provenance: study id + commit + evidence + known failures
```

`candidate` 可用于设计，不得列入玩家可用能力；`verified_backend` 说明局部技术验证，不自动获得准入；`admitted` 必须有明确机器语义、有效后端、适用约束及实际证据。视觉质量在样本与迁移中人工审阅，不能由状态字段自动认定。

### 5.3 模型生成与读解应如何验证

每轮新增配方需记录对应 RuneContributions（以符文节点/组引用真实 Subject/Relation/Process/Contract），区分明确锚、模型补全及纯艺术选择；任何新增实际能力都说明来源与代价。玩家不必加「以太」才允许通常的异常成立条件；若显式加入以太，应尊重它对奥术关系/寄托/干涉的语义指向。

当候选规则及可用能力集合清楚时，做小规模真实模型试构：给未见本题标准答案的高能力模型 RuneGraph、情境、事前意向锚、相关知识、能力版本及风格，要求一次生成完整配方；保留原答，明确一次诊断修正，别把人工修正算首答。只开放本轮实际可解释的能力。模型不存在于战斗循环。还原解释由配方反向生成，而不是复制模型散文。未锚定艺术选择可以有多样性；备选锚必须带有因果差异，不为颜色与数值换档提供伪选择。

纸面读谱实验不是实际模型执行成功。若暂无真实模型调用条件，应提交可复用输入、期望和实验协议，标为未执行，不得伪造。80%–90% 是后续真实玩家事前预期命中目标，非当前人工案例数和模型准入率。

## 6. 最小编译与 Godot 承接：从第一轮就做，避免大而全的重写

本阶段不要求全语言 Schema 或完整 WorldLaw。要求每个已经施工的现象都能通过一份**可加载、版本固定、可追踪的候选编排数据**进入同一执行路径。人写配方也算编排研究，不能伪称模型生成。设计 DSL 与本轮机器子集允许不同形式，但须有逐项对应，不能只靠口头解释。

### 6.1 从作者谱到可运行计划

1. **构筑/解析时**：固定版本；验证类型、单位、参照、局部端口和上界；展开 fragment/use/each 的静态部分与艺术组；保留有界运行时选择与实际状态绑定。补齐已登记默认，标记缺失能力。最终保留对源配方的定位信息。
2. **建术时**：获取真实参照、来源、权限和责任；预留资源；生成有稳定 id 的主体、关系、进程和舞台实例；确认实际成员。报价由版本规则决定。当前研究如仅能使用有限实验额度，明确标注，不能当作完整计费完成。
3. **运行时**：物理固定步采集旧快照和输入，仲裁本步资源、身份、控制和作用请求，向 Jolt 交付合格的物理操作；实际碰撞、位姿和效果结果发布为下一步状态与回执。不可把已发生的引擎运动当数据库事务任意回滚。
4. **演出时**：根据已提交的 snapshot、只读状态和事件推进艺术组，插值表现位置，按实际事件消重；艺术图不得回写世界逻辑。可选轨降档，必需的交互边界和提示保留。

`WorldPlan` 与 `StagePlan` 是同一配方的两种派生执行视图，而非两项独立法术。可直接使用结构化 JSON + 小型确定性 loader/validator/lowerer 支撑本轮，不必先写完整文本 parser；必须说明每个候选字段如何对应 A–D。临时手工编写规范化计划可以作为中间验证，但不得长期保留两套手工重复配方并宣称编译已打通。

### 6.3 推荐技术原则（原计划保留与修订）

| 方法 | 具体做法及质量边界 |
|---|---|
| 动态骨架、曲线与截面 | CPU 在固定步更新有限控制点及帧，弧长重采样；平行传输按顺序在 CPU 或预处理产生，GPU 插值帧时重新正交化；正确处理零长、反向、尖角、自交、封闭接缝。固定拓扑缓存顶点域和索引，GPU 变形或必要的顶点更新；局部拓扑事件才局部重建。扩展合理 AABB，法线/切线、UV 及遮挡不能留在初始状态。 |
| 连续曲面与材料 | 用路径/曲面参数域组织截面、扭转及厚度；真实流体只求有限分段量、流路与边界，艺术高精度网格从共同数据采样。实际碰撞代理用胶囊、凸段/分面、扫掠等有限方法，不每帧重建复杂动态三角网；检查实际轮廓和代理误差。 |
| 场与流动 | 真实 `a(x,t)` 是加速度或作用规律；艺术 `u(x,t)` 是独立的有界运动/速度场，可从真实方向和强度派生。不能混淆二者单位或将粒子轨迹当作真实力学求解。解析轨迹与实际积分两种 GPU 方案都可用，选择适合的；运动相位、种子、连续性明确。尾迹使用固定容量真实历史或明确的纯艺术历史，不能把当前速度反推的直线冒充真实过去轨迹。 |
| 光学与材质 | 按现象选择实际渲染路径：不透明深度写入、alpha/加法合成、解析光学厚度、有限密度采样、场景深度软边等。暗核可由低密度或遮罩形成，未必需要实心球。透明排序、遮挡及深度测试要逐相机验证。背景折射、局部环境光只在许可内近似；不得冒充真实可见性/光学作用。以现有 Godot 4.5 Forward+ 为准，先做相应小样，必要时查官方接口，确有需求才引入额外合成通道。 |
| 动作 | 选取或制作符合定位的真正骨骼片段，身体重心、脚底、脊柱、肩手、武器、衣袍、预备/卸力应共同成立。AnimationTree / AnimationPlayer 与实际动作事件对齐。浮空、移位或抗击退若有玩法意义须由实际角色/世界契约支撑；纯表现不改 hitbox。三组 Euler 关键值不自动等于高品质动画。 |
| 音频和导演 | 使用有艺术完成度的分层资源，按实际过程与回执组织不同起音、节拍和尾声。预备声床不能预测未发生的输入；命中反馈仅响应实际事件。允许自由镜头，不用强制镜头替代动作重量。环境构图与混音按室内/外适配，不能让多术重叠毁掉可读性。 |
| 性能 | 逻辑/物理目标 60Hz；必要的动态构形与代理按固定步，纯视觉可降采样并逐帧插值。避免逐帧大量 Node、材质资源、数组和粒子创建；重效果按屏幕覆盖、透明过绘、灯光、粒子、动态网格和可查询对象预算。预热、对象池、质量档都按实际瓶颈使用。先测高质量局部效果实时运行；产品 P95≤16.67ms 与显存≤2.5GB 仍须在完整负载、M6 Metal 与中端 Vulkan 环境最终验收。 |

上述技术选型必须由艺术目标驱动。不要以「用了 PTF、GPU 粒子、PBR」当成质量达标；不要因计划列出某种渲染方式就机械应用于所有意象。初始参数和更新率只是工程建议，按测量和审美评审修正。

### 7.2 先提交三种真正不同的设计方向，再确认研究命题

| 方向 | 可用的自然构筑（示例） | 现象与交互 | 艺术人格 |

三种方向不能靠同一个球换属性解决。不要把它们一次塞进同一术；也不排除未来由玩家主动组合。以下以「重力天体」暂名“沉星”为**可供确认的设计与技术示范**。负责人如选另一个方向，依同一流程改写，不把重力方向视为已批准或玩家默认必须获得的解释。

### 7.3 “沉星”设计命题（供审阅，名称仅用于定位文档）

**核心体验**：玩家不是投出一颗月亮，而是在空间中建立一处异常引力中心，能把周围质量体的运动引向它。引力的规模与持续时间具有实际代价，形成、操控、结束均可读；没有碎石时仍能正常形成。场地有敌人、落物、其他法术实体或可活动道具时，同一配方按共同资格产生作用。

**核心锚**：`重力`＝局部对质量体的加速度；`聚`＝运动朝共同中心汇聚，不自动将材料熔合；`引`＝选择/引导中心，须注明是否实时引导。可选沉降轨迹是中心的组织方式，不自动赋予另一个全域向下重力；本候选不增加火、冷、光学遮挡、解魔、自动旋转、范围爆炸、吸取生命等作用。若模型选择这些附加实际能力，必须有相应意向与独立契约，而不能因艺术参考暗月而照搬。以太承担异常场的成立依据；魔力支付建立、维持和扩大能力。

**交互推荐**：瞄准一个合法位置，按住进入有风险的聚势；根据配方限定小范围调节目标中心；达到实际最低责任后松手，交付有限持续时间的沉降/汇聚场；未达到门槛则取消未交付部分。松手前被打断，不出现尚未提交的交付。若设计选择在蓄势期就有真实弱引力，必须另行写清持续付费，已产生的运动不回滚；此候选优先采用“蓄势无真实外物牵引、交付后才施加”的版本以清晰区分两者。后续可研究蓄势期间已有弱场的变奏。

**构图思想**：让观众先读出一种即将收束的空间方向，再看见一个超出实体物件观感的中心；整个演出具有大尺度秩序、稀疏负空间、局部密度变化。暗核可以是光学意象或视觉包络，不等于实心质量体。核心形象不一定使用月面；应比较抽象暗核/层状冷光等方向的整体分镜，避免写实天文模型与装饰环抢占角色及环境。

**核心设计规格（示例起点，须由作者和负责人确定最终值）**：最大实际作用半径约 4 m、中心在可瞄准/合法位置，蓄势上限约 2.5 s（符合 1.5–3 s 慢拍动作目标），最低支付门槛由报价派生；交付后维持约 1–1.5 s，中心可按明确曲线在净空内沉降，最小近地高度明确。选择远近及强度时记录上界；不得把这些示数固化为重力原语的永久能力。初始研究可以用有限实验额度，但必须标记为非正式玩家蓝耗。

| 节拍（非强制四拍） | 真实现象与交互 | 艺术构造/可读性 | 要避免的错误 |
|---|---|---|---|
| 预备、聚势 | 有效目标、输入与付费积蓄；尚无已交付外物加速度 | 局部空间中的收敛纹理、姿态建立、声床渐强；聚势预示与活动作用边界分离 | 未作用却让真实碎石提前浮起；按固定秒数擅自释放 |
| 交付、成形 | 成功交付，有限引力域开始施力；中心按已确认的轨迹/目标移动 | 整体宏观剪影完成，方向性流迹与实际外物响应共同表达汇聚；主重心从施法者转向异常区域 | 仅把预制球变亮再飞出；施法者无依据浮空 |
| 持续、沉降 | 每步按真实范围、场强、实际对象及预算施加力；到地面附近中心停在许可位置，场仍按契约存在 | 外围对象轨迹、局部密度、地面接触和声部逐渐汇聚；环境有尺度参照 | 触地自动销毁；画面旋向与实际场不一致；把艺术流迹当作实物 |
| 终止、余韵 | 断供、到期等使未来额外力为零；保留已经取得的速度与真实接触后果 | 中心与视觉层各自有明确收束/衰减；实际物体自然继续运动，声尾完整 | 尾迹继续跟踪隐藏目标；用爆炸掩盖没有作用；自然物随特效消失 |

实际动作事件（commit/release）与回执是时间锚。用连续时间研究构形，但不要把每个局部都捆绑到同一个 progress。初版导演的 7.8s 固定剧本只留为回放工具，正常交互需接受真实 hold/release/interrupt；ArtLab 拖动时间用于重放已记录输入，不能把任意时间轴跳跃等同真实世界因果执行。

### 7.4 配方必须和演出同时出现：示范 DSL 候选

以下**不是新正式语法，也不宣称旧 Schema 能准入**。它用于让工程 Agent 看清作者意向如何落到现行六面、待定义的能力与艺术组织。优先将含义用现有 A7/C5 的几何、组、局部驱动、B/D 的关系和过程表达；新增字段/语法只在不能表达时加入，并在 `mapping.md` 给出精确定义。不得直接复制下面的示意名作为术名分派。

```text
INPUT RuneGraph = group(gravity, gather) -> guide
ANCHOR: local mass acceleration toward chosen spatial centre
EXCLUDE: heat removal, world optical suppression, intrinsic mass body,
         automatic tangential rotation, collision-triggered blast

C gravity, local_arcane_basis, finite_scope
S field = manifest(gravity, sphere(R), capture(aim))  // R 有有限上界
R pull = gravity(field, within(field, mass_bearing),
                 distribution=radial_profile, basis=paid_support)
K charge = finite_mana_reserve(caster, quoted_capacity)
K responsibility = controller(caster), payer(charge/declared_provider), deadline
K pilot = bind(prepare, aim, desired_center, field, rate_limit, legal_space)
P prepare : charge; maintain legal desired centre
    on interrupt -> settle_unspent; end
    on release if paid_threshold -> capture legal centre; enter deliver
P deliver : establish paid_support
    tick move_field_center(descent_profile, within_legal_space)
    tick apply_local_acceleration(pull, paid_strength)
    on depleted / timeout / forced_interrupt -> withdraw support; end
// 撤场保留真实对象的动量、接触及已提交损伤；不建立实体球体。

X group primary @local(field.frame) {
    // 核心形态由空间密度与局部相位构成，非游戏碰撞体
    visual composition = bounded_density_form(core_profile, outer_profile)
      drive = phase_map(spatial_coordinate, paid_progress_or_committed_elapsed)
    visual streamlines = sweep(local_cross_section, sampled_visual_flow)
      drive = spatial_phase; follow = shared_frame; curvature = authored_profile
    visual interaction_edge @real(pull.boundary) = readable_required_boundary
      while = active(pull); stop = exit(deliver)
    visual wake = bounded_history(actual_center, 8..24)
      start = commit(delivery); stop = exit(deliver); tail = authored_decay
    // 根据分镜定义局部明暗、疏密、相位、纹理、相对尺度与帧，不只列标签。
}
X body / audio / camera / environment = explicit independent tracks
    bound to actual pose, enter/exit, receipt and lawful artistic clocks
```

说明：`EXCLUDE` 是构筑意向/锚检查，不是必须放进执行体的新顶层字段。`paid_support`、`move_field_center`、`bounded_density_form`、`phase_map` 等是待映射语义。`gravity` 调用需与现有局部重力签名校准（现稿 B4 主要 up/down；向心方向、可移动参照与分布可能是本轮确有价值的扩展）。`while active(pull)` 不能用艺术图作为世界真值。`camera` 不默认强制镜头；`wake` 的 8..24 是可调历史采样上界示例，实际取有限整数，按需要调整。

作者还须提供**明确可加载的本轮编排数据**，不能只交这一段伪谱。例：将域形、参照、分布、强度、中心演化、进程、艺术局部、材质资产、参数曲线、事件与退场写成 JSON，再由小型 loader 逐字段读取。数值应由审阅后的设计填写，实际付费和上界由可复现规则给出。具体的视觉几何可由已声明资产/构造器实现，完整演出不以文件名/法术名跳转。

### 7.5 技术映射：使其在真实世界中成立

**世界计算**：实际引力域为有限球域或明确有界形状，中心 c(t) 取已实现状态。一个可供研究的径向分布为：

```
r = |x - c| ;  u = r/R
w(u) = (1 - u²)²          (0 ≤ u < 1；域外为 0)
a(x,t) = A(t) * w(u) * (c-x) / max(r, epsilon)
```

epsilon 为中心软化距离，解决中心奇点；轴向、切向若无锚/补全不添加。A(t) 以 m/s² 计，受实付强度、版本上限及场的有效时间限制。质量 m 的物体申请 F=m*a。若本步冲量/功/反作用端存在共享上限，按 B/D 的固定分配规则缩限真实交付并产生回执；对运动目标的动能变化和反力来源由选定合同明确，不用“魔法”逃掉付费。没有完整能量计费时，只能证明有限实验条件下的交付。力学字段须区分 `requested` 与 `delivered`；不能因改变参与对象数量而出现未经设计的“最后一个物体获得无限力量”。作用强弱可因共享配额竞争降低，法坛要据实说明。此为候选模型，不声称真实万有引力模拟。

- Godot/Jolt：用共享世界接口查询有受力资格的对象；刚体通过力/冲量接口提交，角色通过现有角色受力与失衡接口接收实际运动影响，不能对 CharacterBody 直接调用刚体 API。避免新建仅对敌人/特定道具有效的术名逻辑。既有 `hall_world.gd` 将冲量直接扣完整性/韧性的做法不能拿来等同持续牵引损伤；平稳外力、真实碰撞、结构负载和角色受击分别处理。重力默认不是普通压力射线遮挡，具体异常场遮蔽如需要必须显式设定。
- 中心运动：在本轮按合法参照、有限速度/位置、沉降曲线与失联策略更新实际场中心。域不是刚体，不因为视觉核心接触地板判为撞击；中心受净空/边界策略约束，地面真实对象依 Jolt 接触结算。瞄点快速跳动不许把实物瞬移。实际中心、范围、强度、已交付力与历史写进共享状态。
- 演出流动：取实际中心/方向/强度的只读数据，另设计艺术速度场（量纲 m/s 或明确归一速度），保持主收敛方向。可选解析采样曲线或有界积分、柔性截面、局部相位、明暗密度；没有真实旋向时不得用强烈旋转暗示实际旋涡。细粒子可有不误导的局部扰动。真实碎石和装饰粒子分别建账/渲染；装饰无碰撞与玩法权限。
- 形态承接：至少写出一条与整体形态有关的非整体缩放演化，例如不同半径层的局部密度/轮廓沿空间相位重新组织，或连贯的曲带由松散到内收并在退场后解构。明确参数域、局部对应、时间与实例身份；改变目标/提前释放时不跳变为另一组模型。主体没有自然球体碰撞即不要使用物理球去伪造交付。
- 光学构成：先看灰阶主剪影、前景/中景/远景及建筑尺度，再确定渲染。可探索少量不规则密度层、深度裁切软边、稀疏高光、局部明暗反差；必要时使用受控光学近似。不要因为旧代码已有球壳或三条曲带就强制复用。实心不透明艺术核心会遮挡玩家画面，即便无碰撞也必须考虑可读性和真实光学语义；不要制造“可藏身”的假安全感。
- 动作：以站稳并承受/引导异常力量为候选，不默认漂浮。对比无特效动作、无动作现象、完整演出三者。角色姿态、准备窗口、实际释放、恢复和受击打断应对应。若需真实浮空、反坐或位移，另行声明责任及控制。
- 音频/导演：以低频张力、方向性空气/石材响动、交付成立的清楚瞬态、自然余韵为候选；真实碰撞声只在真实接触回执出现；无接触则不响。不可预知松手前不强行制造固定静默。镜头以正常第三人称为验收主机位，艺术机位只辅助分析。

**最小联合验证**：一个有真实普通地面/障碍、两种质量的可动对象、一个角色受力端及一个可合法作用的既有魔法实体的研究场。若某对象类尚无适配器，则明确标缺口，不把它当已支持。用同一 recipe 在工作台接受真实按住/松手/取消（或记录输入回放），不是按时间表播放自制动画。记录真实中心、域边界、实际力/对象运动、事件、演出绑定和尾迹历史。视觉目标应在该真实响应基础上成立，而非依赖脚本预置碎石悬浮轨迹。

### 7.6 这一轮应给 DSL 与未来编译留下的知识

不是把“沉星”命名为一个新能力。要检查是否有以下可普遍复用的贡献：

| 候选贡献 | 为什么值得抽象 | 如何验证不是专属技巧 |
|---|---|---|
| 有移动参照的有限场 + 有界方向/分布 | 向心、向外、下压、局部引导的共同机制 | 改方向与中心轨迹，不换世界后端；其他普通物体仍参与 |
| 空间相位的渐进构图与密度重组 | 不只生成一个放大的物体 | 同一方法用于光带、水流或雾的显形；构图和节奏可变 |
| 实际方向/强度到艺术速度的显式派生 | 统一运动趋势而非机械同相 | 保持世界作用不变，改变艺术速度、宽度及分布，因果不变 |
| 交付/退场时的动态状态承接 | 场、流形与实体都需要连续历史 | 改目标、提前释放、断供仍无跳变或虚假新作用 |
| 重量感与方向可读性的创作原则 | 让模型选择自然形态、动作与声部 | 改为沉重/克制两种编排，玩家仍能辨认共同作用 |

本轮至少留下一份非天体的新构思，使用同一主要机制而具有不同艺术形象；例如一个开阔地面上的收束压场，主体不是球、也没有偏轴环。另挑一项相邻意向（例如气流向心汇聚）尝试迁移空间构造和艺术流动，不要求本轮完成完整风暴后端。优先验证真实迁移；若只有纸面配方就标纸面。禁止以新建 `Celestial2.gd` 或完整“沉星”母版变种代替编排迁移。可发现缺少新领域能力，允许真实的通用后端补足；不宣称所有效果必须零新代码。

## 8. 后续研究组合：不是独立完成五个特效再回来

以下是优先研究的构成跨度，不是最终固定法术表，不是必须按编号串行的“五大模板”。每轮都同步更新语言、能力、知识、配方与实机证据。每个研究方向的起点是有艺术价值的自然魔法意向，技术方案以能兑现意向为准。

| 研究方向 | 值得创造的现象（候选） | 重点加厚的表达与技术 | 必须做的迁移/区别 |
|---|---|---|---|
| R1 场与空间秩序 | 沉星或经确认的天体性质魔法 | 参照、分布、方向、强度演化、时空构图、身体与环境 | 同场不同形、同形不同实际作用、空旷/有对象/障碍附近 |
| R2 连续流形与柔性界面 | 水、聚、引的银河垂流；光、守、联的折天之帷可作为相邻构思 | 骨架与截面、局部滞后、有限分支/重组、构图承接、实际材料/约束与艺术流动 | 水带改变方向、局部失权或凝固；真实光幕与纯艺术光带区别；不能把两种法术强制合并 |
| R3 宏观流动与环境 | 气、聚、引的旋风或风浪 | 复合场、空间相位、体积层次、场与实际运动、室内外导演 | 去掉上升/切向的真实差异、不同构图风格、真实环境响应 |
| R4 结构组织与存在历史 | 浮岩王冠、岩晶生长、具有真实承载的动态构造 | 离散阵列与连续结构、稳定身份、局部损坏、材料份额与力学通路、纹理/断面 | 留存、后术重新借取；不同布局与普通碎石场景；不要求所有岩石自带榫口 |
| R5 隐微作用与复合关系 | 雾中之眼、微光感知、解魔或静谧领域 | 光学/信息/以太独立通道、克制构图、局部真实事件、观察权限与多术关系 | 同样外形不同因果锚；断信息线保留遮蔽；清晰可读但不泄露信息 |
| R6 跨结构与艺术形式的新构筑 | 由独立设计者提出此前未见的宏观形变、局部寄托或多场复合 | 动态组合闭合、复杂编排、模型自然构思及艺术风格跨度 | 重新组织已有能力，不按术名特判；重要语义缺口明确反哺 |

避免把“每轮至少一份艺术迁移”误读为每轮完整制作六个发布级法术。每轮先集中解决最重要的创作难点，在能力版本上做小规模真实迁移；下一轮延续更难的艺术与领域挑战。选题可交叉推进，未过审的效果不进入已认可能力集；独立光学研究或动作素材制作无需等待前一个样本被无限打磨。重点保持研究质量，不以编号完成率为成果。

## 9. 实际验读、审美评议与迁移验证

### 9.1 分开判断五个问题，不允许互相替代

| 维度 | 怎么看 | 失败怎样处理 |
|---|---|---|
| 意向/设计 | 先看自然意向、符文图、核心锚和可预期交互；是否值得玩家主动创造；是否有普遍用途 | 改设计或编译知识；不以特效漂亮替代核心意向 |
| 表达/编排 | 完整谱是否能描述预期形态变化、构图、控制、世界作用、退场；是否存在谱外特判 | 若语言缺少组织规律，扩展候选语法；若仅缺领域/资产，标相应能力缺口 |
| 解析/技术 | 隐去标题及散文，由不同读者独立读谱；加载后对照状态、事件、身份、参数和实际反馈 | 修订规范、展开或后端；有歧义不伪称已稳定 |
| 艺术/体验 | 真实视听是否有完整剪影、尺度、层次、形态连续性、力量、节奏与可读性；普通玩家视角是否成立 | 人工明确失败镜头和原因；重新构图、运动、资产或导演；不以通过测试作为审美通过 |
| 生成/迁移 | 独立构思、换形/换组/换用；未知 RuneGraph 是否自然生成可运行构筑 | 区分知识不足、DSL 缺口、模型错误、后端不足或艺术失败；保留首答，不偷偷改题 |

不要求每个评审者对所有审美细节意见完全一致；项目负责人决定整体风格，记录依据。对相同配方、同一世界及输入，实质世界语义必须一致；艺术读谱至少能还原主剪影、主要形态演化、局部关系、节奏和反馈，而不是只猜到颜色和元素。

### 9.2 实际视听证据最低要求

每个进入联合评议的研究样本保留完整连续录屏（含音、直到尾声真正结束）、自然第三人称主机位、必要的侧面/背面/远近、关键时点图、分层与灰阶剪影。比较单层的实际作用/形态及完整构图；可用静音和遮蔽特效对照动作。场景尺度通过建筑与角色体现，室内外适配不得改变世界真值。大型、小型、低光、高反差等情况按样本需要选择，不规定所有法术一律六帧四层四拍。

再录制真实可操作的输入：提前/延后释放、持续引导、转向、打断、失去来源或责任、邻近其他现象等与本轮有关的变化。脚本回放可帮助复现，不可把固定剧本当交互通过。未能提供实机视频或无法观看/听取时诚实标明；不声称已完成完整视听评议。自动化可以检查状态或生成证据，不替代审美判断。

### 9.3 迁移应证明的内容

每轮至少做两个正交对照（取与本轮最有关者，最终覆盖全部维度）：

| 对照 | 不变量 | 变化量 |
|---|---|---|
| 换形 | 世界机制、控制、报价和实际对象 | 艺术构图、材质、运动与节奏 |
| 换质/换作用 | 共同空间或艺术组织 | 本性/成立条件/通道及相应真实后果，不能视觉误导 |
| 换序 | 主体与核心意向 | 发生次序、时空相位与交付窗口 |
| 换责 | 已形成内容 | 控制者、供给、存续与交接 |
| 换组 | 局部片段及其明确端口 | 整体构图、嵌套、空间排列及协同 |
| 换用 | 同一已确认配方（哈希保持） | 普通场景、目标、障碍及玩家用途 |

“零新法术专属代码”是研究手段：在选定已支持的通用能力版本上用新配方做变化，检查不需要改引擎分派才能成立。它不是禁止将来新增优秀技术或资产；若必须加代码，要诚实标注本轮缺口、独立价值及复用范围，而不是把新专属后端伪装成已存在的能力。某个变奏只改美术时不得增加 WorldLaw 能力。

### 9.4 失败分类与纠偏（Agent 必须填写）

- `design_intent`：魔法定位错误、玩家不会自然产生该意向、用途过度特化。
- `composition_semantics`：几何/形态/局部组的组合意义缺失或不唯一。
- `stage_expression`：配方不能表达必要的构图、形变、节奏和主次；不是简单少一个特效名。
- `creative_knowledge`：语言能表达，模型不知道为什么要这样构思；添加有证据的原则/对照，不新增强制术名模板。
- `capability_backend`：语言语义清楚，但后端尚无足够算法或领域支持。
- `asset_art_direction`：机制能运行但资产、光学、动作、声音、构图不够好；改善技术美术，不乱改世界机制。
- `interaction`：实际控制和动作节奏不适配；区分语言可控能力与玩家交互映射。
- `admission/runtime/performance`：类型、权限、调度、预算、性能等工程问题；只在相应层修复，保留证据。

同一失败可多类，但必须指出主因与具体修复。不能笼统归因“模型不够强”或“Godot 不够好”，也不能以“已增加字段/通过测试/使用高级 Shader”结案。

## 10. 从研究走向正式开发：分阶段，但每阶段内联合演进

| 路线 | 当前行动 | 进入下一层的条件 |
|---|---|---|
| A：联合研究基础（立即） | 改正现行协作规则；审阅首版并确认下一构思；连接最小配方 loader、共享状态和艺术图；保留旧运行版本 | 有首份完整的设计、DSL、映射、知识与真实后端的联合交付，能从普通输入运行且诚实记录缺口 |
| B：持续加厚与扩展 | 按 R1–R6 的构成跨度研究，反复做编排、艺术实现、自然意向、跨场景与异质迁移；持续改 A–D、知识、能力契约与小型编排解析 | 新构思主要复用已有组合规则，艺术构图/动态/作用仍有明显多样性；少数剩余问题可定位为领域/资产/后端缺口；重大语义分歧已解决 |
| C：候选语言规范化与表达实验 | 固定实验候选版本，独立设计者出题，完整编谱、隐名独立读解、六维变奏、实际高能力模型首答与改锚；逐步统一 Schema、类型和能力注册表 | 在计划开放范围内，配方可准确解析、意向可追踪、创作自然、重要美学形态可表达；无靠题名特判；已认可后端能兑现。候选不必覆盖所有远期时/生/空能力。 |
| D：通用能力施工与废墟整合 | 将已认可的现象/艺术构造、契约、统一执行器、玩家动作与法坛合流；在立体废墟普通对象上检验不同法术交互 | 按稳定版本执行，同一配方换场景成立；可玩、可读、真实余留和跨术关系成立；艺术品质在实际第三人称中保持 |
| E：产品与模型闭环 | 真实玩家盲测、运行性能、资产优化、生成记录、SFT/RLVR 评估 | 原计划的 80%–90% 事前预期命中目标与 1080p60/显存目标分别独立验证；训练数据含许可、来源、首答/修正、后端观测及真实偏好 |

A/B 已能实现足够关键的技术与局部解析，不需要等到 C 才有可运行配方；C/D 不是第一次考虑 DSL 或第一次接实际世界。相反，C 只是将已研究的通用规律正式规范化，D 才扩大到完整产品执行和关卡。这避免两种极端：只写纸面语言到永远、先做漂亮技能再强行接 DSL。

### 10.1 不以数量或速度为冻结依据

没有“完成五个样本就自动冻结 DSL”的规定，也没有“原语必须 ≤20”或“所有法术必须四拍”的指标。语言基本稳定的判断依据是：

1. 经典参考中重要的构成原理能够映射，独立原创不再受已有示例外观支配；自然符文意向有意义且可读。
2. 空间、动态形态、时序、局部片段、责任与艺术组的组合具有清楚、可复用、可解析的含义；组合后的材料/作用/艺术状态不依赖作者口头补丁。
3. 同一世界作用能表达不同艺术人格，同一构造技术能迁移至不同意象；动态演化不是仅缩放、贴图、粒子叠加。
4. 隐名读谱与独立构筑能够定位剩余缺口；大部分新需求不迫使重写核心组织模型。高阶领域能力仍可按合同增量开放。
5. 已有局部真实后端、艺术资产和编译数据提供了足够证据，不以文档数或测试数证明艺术上限。

具体独立题规模建议约 12–20 个，视构成跨度和重复程度调整，不追求凑数；在候选版本锁定后出题，禁止为测试偷偷新增专属函数。结论由负责人集中审阅，不由 Agent 自行宣告封版。语言的核心组合规律可稳定，知识、艺术资产和领域能力仍可继续成长。

### 11.3 第一轮任务优先级（实际行动清单）

**P0：先对齐设计与工作方式。** 修订旧计划入口，保留首版；给出三种天体设计的核心作用、符文、整体意象和分镜，由负责人确认方向。同步提交候选六面配方、技术映射、待补语言条款、艺术知识与世界语义。重点确认是否选择重力天体，而不是擅自假设已经决定。

**P1：让同一配方驱动研究实例。** 以最小确定性 loader、共享状态/事件及有界实际后端兑现选定核心意向；在 ArtLab 支持实际 hold/release/interrupt、真实受力对象、同一状态驱动的视觉与音频。设计稿中未实现的真实作用不得用视觉替代。旧 v0.3 继续正常回放。

**P1：同时把整体演出做出来。** 从构图小样、动态形态、正常第三人称视角、身体动作和音画节拍入手，确定最值得投入的技术；先解决整体意象和作用可读性，再精炼材质与微尺度细节。使用对照验证关键形态承接和时空演化。不能把旧球体效果放大、加粒子或仅换贴图作为修改结果。

**P2：基于真实缺口反哺 DSL 和编译知识。** 在本轮结束前形成 A–D 的局部差分与能力签名，写清自然意向的选择依据、审美构成原则、参数范围和负面例；把实际可加载配方与设计谱对齐。提交与另一意象的迁移，并标明纸面/实际证据。能力和知识可逐轮成长，不需要等待五个标杆完成。

**P2：集中评议与下一轮决策。** 提交完整录像、正常镜头与条件变化，提供原始状态与回执。分别评价意向、世界、艺术、表达、技术与迁移；失败分类明确。若主要问题是结构性语言不足，优先深化语言；若是技术美术不足，改善具体实现；若仅缺某领域后端，明确边界。不要把完成功能数量当进度。

### 11.4 每次提交的汇报格式（工程 Agent 必须使用）

```
研究命题 / 当前候选版本 / 提交 SHA：
1. 玩家意向、符文及锚；本次确定/尚待负责人决定的选择
2. 完整现象、实际作用、操控与美学构图；链接设计谱/可加载数据
3. DSL/编译知识/能力契约差分；为何具有独立复用价值
4. 技术映射与变更；实际支持的边界、未支持或降级之处
5. 实机/纸面/模型/人工审美证据，分别报告，不混用
6. 同配方换场景及新编排的迁移结果；有无新专属代码
7. 最重要的失败与下一项创作问题；不要以单测或素材数量结案
```

重要设计决定、未实现内容和临时假设必须明确公开，不默默简化。将源配方、能力版本、艺术资产、证据及代码固定到同一提交。任何正式玩家能力开放、核心语言冻结或世界公理修改都需要负责人确认。

## 12. 最终目标

我们并不希望建造一个能描述无数法术、但实际全由球、环、丝带、粒子构成的游戏，也不希望造出一些精美技能却无法自然生成。我们要让每一次创作留下可迁移的**魔法理解、艺术构成规律、动态技术、确定性语义及编译知识**，使后续由玩家和语言模型组织的现象在自由度增长的同时仍具有整体美学品质。

广义奥卡姆剃刀在这里不是删除艺术细节，而是减少没有独立价值的重复机制，保留具有普遍创造力的丰富规律。真实作用、直观可读性、艺术整体性、自然编译与跨场景用途共同决定项目上限。

**不再把“做好演出”和“做好 DSL”当作前后两个研发阶段。每轮都要让二者共同成长，并由共享世界和实际技术检验其是否成立。**
