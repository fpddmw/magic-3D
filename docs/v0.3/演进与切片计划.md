## 二、设计定调与五条把关护栏

下一阶段的研发重心从“能创造哪些单个现象”升级为**“现象如何在世界中持续存在、被玩家驾驭、跨实例相互作用，并作为后续行为的真实输入”**——即同时加厚 **构成自由度、操控自由度、魔法间自由度、世界用途自由度**。

为防止高自由度把系统重新做肿或失控，后续扩展严格遵守五条硬护栏：

1. **三不增与语义冻结**
   - 不新增顶层块（维持 `Concepts / Subjects / Relations / Processes / Contracts / Expression`）、不新增顶层操作（维持 `Establish / Drive / Constrain / Transform / Transfer / Couple / Withdraw`）、不新增空间载体（维持 `Body / PathGraph / SurfacePatch / Region`），不再扩张形而上学公理与 20 枚符文总盘。
   - **语义验收红线**：玩家明确锚定的核心预期必须能沿符文贡献追溯到 DSL 中真实存在的作用机制与责任；模型补全的形态与细节不得与核心意向冲突。
2. **持续驾驭防失控**
   - 持续控制（`Control`）严格遵循单焦点（`focus: exclusive`），战斗中只开放三类紧凑输入动词：**瞄点/方向引导**、**长按蓄力/维系**、**主动收束/交付/松手**，不做复杂编辑器式 6-DOF 微操。
   - 携带平台或实体托举移动受有限负荷、最大线速度与持续魔力供给约束，杜绝免费无限飞行逃课。
3. **离散有界拓扑，守住物理红线**
   - 动态空间变化与“聚合 / 分裂 / 重组”一律通过**离散有限成员与连接边**表达（单阵列成员 `count <= 6`，每术实体 `bodies <= 16`，全局动态刚体 `<= 64`，`PathGraph` 节点 `<= 16` / 边 `<= 24`，`SurfacePatch` 有限分段单元），严禁任意网格布尔切割与底层连续流体求解器。
4. **语法熵受控与独立三账**
   - 高级能力按需选用。选用后须提供该能力签名要求的参数。离线因果对照允许空 `Expression`；有演出意图时建议选 2–5 条核心轨，由 `ArtKit / Director` 按载体×材质适配器、废城低饱和色板（约 9% 局部高亮带）与室内外声场补全次级工艺。
   - **蓝耗账、物理配额账、渲染开销账**严格独立；重档体积/扭曲轨按单术与全局仲裁限流。
5. **先清性能债，再叠重表现**
   - 在叠入多轨 `Expression`、空间体积效果与更丰富的废墟庭院之前，优先定位并压平雨殿切片的 P95 抖动根因。

## 三、Magic DSL v0.3.1 语法与表现层补强清单

P1–P5 对应 G1–G6 通用能力缺口，沿用现有六段式与七类操作。下列条目按切片分批实现。当前离线证据覆盖 P2 的等半径直柱域和 P3 的三分量持续力。

### P1 · 共享运动参照与有限阵列
- **共享参照**：`Spatial.reference.anchor` 允许引用同配方内其他 `Subject.id` 与角色部位槽（`caster_hand / caster_weapon`），配合 `offset`（`none / overhead / front / around`）与 `follow`（`position / transform`），支持复合主体共享移动核心（例如暗月多场共行而分别退场）与动作挥击派生（例如挥剑释放独立剑波）。
- **有限阵列（`formation`）**：可选声明 `count`（`1..6`）、`layout`（`arc / ring / line / scatter`）与 `dispatch`（`simultaneous / staggered / per_trigger`），统一记入实体配额与计费，覆盖多岩悬停投射、独立触发辉剑与多落点离散放电。

### P2 · 动态空间演化与有限结构连接
- **共享只读快照 `SpatialState`**：统一记录 `reference / realized_geometry / material_distribution / connectivity / occupied_space / influence_space`，供逻辑结算与表现轨共同读取。
- **几何扩展。** `Region.column` 已支持给定半径和高度的直柱域。柱身收窄、`SurfacePatch` 的分段 `segments` 与曲率 `curvature`（剑波、石桥或墙体）、`PathGraph` 的截面 `cross_section_m` 与有限黏附 `adhesion` 均为后续设计。
- **空间演化（`evolution`）**：为 `Transform(grow)` 与持续塑形增加可选 `dimension`（`height / extent / radius / path_length`）、`profile` 与 `obstruction`（`halt / truncate / deflect / slide`）；硬规定**物理碰撞体与 `realized_geometry` 逐帧同步**，禁止出现无形碰撞体领先画面。
- **有限承重链与修复**：支持 `structural_chain`（支点连接拓扑与材料强度），断掉某一支点或中间段后由 `WorldLaw` 重算其余段承重与坠落，而非单一总血量扣减；支持以残余材料补全有限受损结构的修复过程。

### P3 · 三分量有限向量组合场
- 在完全兼容单轴 `axis` 的前提下，配合 `Region` 的 `column`（`radius_m / height_m`）与 `Spatial.distribution`（`radial / axial` 轮廓），`Drive` 持续能力 `sustain_force` 采用 `field_vector`（`radial / tangential / axial` 分量，欧氏模长 ∈ `(0, 1]`）。
- 向心汇集、离心扩散与上升气流均可通过调整三个有符号分量来表达。三个分量共用一次供给对应的固定满额力。各分量按原值乘以满额力，未用份额留空。只将轴向分量置零，径向和切向系数保持原值；只将切向分量取反，其大小保持原值。有效对象再按实际位置与分布共享本步力预算。
- 离线验收采用同一场景、同一配方、同一报价。东侧探针在 1 秒松手时，去掉上升使 Y 速度由 +0.655 降为 0 m/s，水平速度保持一致；反转旋向使 Z 速度由 −0.650 变为 +0.650 m/s，抬升量保持一致。该场景的高度分布均匀，受力期间探针均在柱内。[逐时观测](../v0.3.1/column_field_observations.json)

### P4 · 持续驾驭、运动模式、事件与跨实例干涉
- **受限 `Control` 声明**：定义配方在施展后接受的持续输入绑定（位置引导、姿态引导、结构组织、作用交付），受限速、有限负荷与 collision 规则约束。
- **六种封闭 `motion_mode`**：主体运动模式枚举锁定为 `static`（默认）、`follow_anchor`、`ballistic`、`guided_drift`、`orbit`、`sweep_arc`。
- **触发事件扩展**：`Edge.event` 增加 `proximity`（限定半径且受实际感知/遮挡通道约束）、`overload`（承载超限破裂触发）与 `pose_release`（绑定动作交付帧）。
- **统一储备与多通道分流**：`Transfer` 储备槽支持 `mana_reserve / kinetic_reserve / material_pool`，支撑“锁定运动→记录有限外力→解锁交付”（静止器类机制）以及材料吸纳/储存/回流；单次交付支持按 `split` 权重分配至多通道（如热作用 + 径向冲量）。
- **受限跨实例干涉**：预留 `arcane_support` 通道下的有限 `suppress` 操作，仅对作用域内可查询的外部活跃法术**维持与供给关系**按有限预算施压削弱或切断，不抹除已经自然留存的冰体或石构。

### P5 · 升维 `ExpressionTrack` 与跨层协调
- 废弃绑定具体元素的扁平视觉枚举，将 `Expression` 升级为正交可组合轨道：
  - `role`：`hero | secondary | omen | director`（同一时刻仅允许 1 个主体拿主导权重，阶段切换时平滑交接）；
  - `anchor` 与 `geometry`：`realized | realized_front | independent_aura | scene_sky`（`small` 规模与纯瞬发禁止调用 `scene_sky` 天象以保反差）；
  - `form × material × motion`：延续并扩展 `material × carrier` 专属 Shader 适配（如片岩、晶质、银雾、折射水、火核、曜光、吞光暗、奥术蚀刻），拒绝万能 Shader 硬套四载体；
  - `driver` 与 `relative_timing`：支持 `process_progress / growth_front / load_ratio / velocity / fill_ratio / actual_impact` 与多种参数曲线，允许不同轨道按各自节拍异步演化（主体成形、内部蓄势、环境张力与爆发交付各自成拍）；
  - `tail_s`：支持次级余韵与混响在法术退出后独立渐隐。
- **可读性与渲染分档校验**：承重结构须有应变/裂纹或破裂反馈，光学遮蔽 `hero` 须绑定真实边界，引/推须表意方向一致；按轻（不透明体 / Decal / 全局调色）、中（条带 / 单层折射面 / GPU 粒子）、重（体积雾 / 扭曲壳 / 动态阴影灯）三档独立记账，单法术最多 1 条重档体积轨。

## 四、四阶段实施路线（Gate 0 + 切片 A / B / C）

DSL 增量随对应切片按批次做离线对照。实机路线按 Gate 0、A、B、C 推进。每次验收都记明交付类型、版本和观测范围。

| 阶段 | 核心交付 | 关键验证目标 |
|---|---|---|
| **Gate 0 · 现有雨殿性能** | 在已接入的雨殿战斗负载上建立可重复的帧时间基线，定位慢帧并复测改动。 | M6、Metal、1920×1080，三次独立启动的正式基线配置各自 P95 ≤ 16.67 ms，报告峰值显存及超时帧数。 |
| **切片 A · 风、力量与持续驾驭** | 落地 `column`、三分量向量场、`Control` 持续位置/方向引导、多类对象响应（碎石、悬挂物、角色、已有魔法实体）与多速气流/尘埃/雨雾应和演出。 | 验证“施法后仍可改变走向与范围”，以及冻结能力后直接由模型生成未见新配方实机生效。 |
| **切片 B · 材料、结构、废墟庭院与世界建造** | 将单座雨殿扩展为紧凑立体废墟庭院（断桥、水渠、支点柱、石料、悬重、视线窗洞与巡逻守卫），验证碰撞体随结构生长、分段承重与局部断裂、材料借用、转移、熔融、碎裂、修复、原位交接与应变反馈。 | 首项实机对照用两次独立施法追踪同一份水从取出、冻结、撤术到融化回收的全过程。 |
| **切片 C · 复合主体、自主关系与跨实例干涉** | 落地多主体共享移动参照、局部契约与分离存续、光学遮蔽与信息感应独立组合、`proximity`/扰动触发、器物与外力储备账户、跨实例支撑削弱/切断、`scene_sky` 天象与多速分层导演。 | 验证复合魔法在不同局部退场后各自成立，且跨实例组合在废墟庭院里可读、美观、无专属法术特判。 |

> **关卡协同原则**：废墟庭院里的断桥、水渠、悬重物与视野结构只提供**可被物理和世界规律利用的现实条件**，严禁编写“只认某法术名/ID”的解谜锁。

### Gate 0 的第一轮测量

1. **先复现基线。** 固定代码提交、Godot 4.5.1、雨殿场景与原战斗序列，在同一台 M6 上以 Forward+ / Metal、Jolt、真实 1920×1080、关闭垂直同步运行下方命令。独立启动三次，每次预热 75 帧，再采集 300 个绘制完成间隔。逐批保留 `HALL_BENCH` 输出，核对实际渲染尺寸、P50、P95、最慢帧及帧号、超 16.67 ms 帧数和显存峰值。[现有采样入口](../../game/runtime/acceptance.gd) · [历史对照](evidence/metal.json)
2. **再定位慢帧。** 对照施法、翻滚和近战的帧号，在相同负载下采集脚本、物理及渲染耗时。历史 Metal viewport GPU 计数为零，归因时视为缺测。必要时用 GPU 帧捕获，或每次只改变动态阴影、透明效果中的一项，比较慢帧出现的位置和频率。
3. **用正式配置复测。** 对有证据的瓶颈做调整后，按第一步重跑三批，逐批与基线比较。诊断时临时关闭效果的批次单列。门禁结论注明设备与场景，中端独显和长时战斗另行实测。

```sh
godot --path game --rendering-driver metal --resolution 1920x1080 --disable-vsync -- --hall-bench
```

### 切片 B 的首项实机对照（待验证）

从游戏正常入口连续施放两份已准入配方，记录两个独立的施法实例 ID。现场准备一处已计量的水源、一处接收容器，在两次施法之间保留同一世界。用水的质量核算收支，冻结和融化只改变相态。

| 时点 | 施法与世界行为 | 要保留的观测 |
|---|---|---|
| 取水并冻结 | 第一术从水源取出质量为 m 的一份水，在目标处冻结成冰段。 | 水源质量减少 m，冰段质量为 m，登记材料身份、冰段实体 ID、RID、位置和相态。 |
| 第一术完全退出 | 撤销第一术，释放控制句柄、停止供给，由世界继续持有冰段。 | 第二术启动前，原位冰段仍有同一实体 ID、RID、材料身份和质量。第一术已结束且不再付费。 |
| 独立引用并回收 | 第二术从现场重新选取该冰段，融化后转入接收容器。 | 第二术命中此前记录的材料与实体。接收容器净增 m，原冰段可取余量降为零。水源、冰段余量与接收容器的质量合计在各步守恒。 |

反例使用同一检查点，在第二术启动前把冰段移出其查询范围。第二术应报告缺少目标，容器净增为零，水源维持第一术后的余额，移走的冰段仍持有 m。这样能发现第二术按旧句柄取物、重复扣源或凭空补水的问题。既有雨殿的结冰碰撞与石块交接观测可作局部依据，此链的通过条件是上述两次施法的完整实机记录。

## 五、远期能力边界（v0.4+，不纳入本轮 A–C）

以下方向已完成语境与边界推演，但暂不进入本轮运行时施工，避免拖垮核心手感与性能打磨：
- `时`（局部过程演化速率）与 `生`（活体生长与生态资源模型）两枚延迟符文；
- 大体积控水分海的真实水量排开与自然回流（本轮仅保留离散蓄水段与边界约束轻量验证）；
- 独立声学世界通道（沉默术）、非实体幻象投影与观察联动、复杂自主活化 AI、远端观察渲染端口（侦测术）、双面空间传送门（奥术之门）。

## 六、法坛实验与后训练数据飞轮

法坛实验按冻结的能力版本开展，可从当前离线能力开始。Gate 0 的帧时间测量按既有战斗序列独立进行。

1. **先登记开放范围与玩家预期。** 每轮用高能力模型试构，保存开放词表、三种连接方式、世界能力子集、DSL 与模型版本。当前从 20 枚总盘中的 18 枚开放词选取，`时`、`生` 延后，`空` 限已支持的参照与有限区域。玩家在看到首答和法坛读解前写下核心预期。按冻结的能力表标记未开放请求，单列请求数、总数和原因。
2. **区分首答、修正与改锚。** 保存同一试次的初始锚点、原始首答、确定性读解、准入诊断、至多一次修正、玩家选择的改锚及最终判断。离线与实机观测分别标记。逐步报告命中数与试次数。首答以开放范围内的全部试次为分母，首答准入失败也计入该分母。诊断修正以进入修正的试次为分母，沿用原预期。改锚以实际选择改锚的试次为分母，记录新锚点和对应预期。后两项均保留原始首答的判定。80%–90% 专指玩家首答预期吻合率，现有两次设计方试构单列。[法坛契约与训练记录](符文与编译契约.md)
3. **后训练。** 待 A–C 的能力在实机跑稳、积累可回放的编译记录、世界观测及玩家偏好后，再启动本地小模型 SFT 与 RLVR。
