# Magic DSL v0.3 正式规范 · 离线配置 0.3.0

构筑期模型生成唯一的确定性执行配方。游戏代码按共享能力解释这份配方；引用解析、计费、缓存与 Godot 内部数据布局均可由程序派生。六部分是同一现象的描述维度。配方根另有 version、显示名 name 与规模 scale；名字只供显示。

| 声明 | 身份与语义 |
|---|---|
| Concepts | 有限知识目录中的本性。概念层取得固态水的认识，不产生现场相变。 |
| Subjects | Material、Field 或 WorldRef。来源可写 Manifest、Borrow、Reference、Derived。建立场、取得材料或读取世界槽位分别有操作与绑定责任。初始相态是对借入材料的现场前提；额外性质通过 properties 引用提供能力的实际关系和过程。当前离线支持表仅准入已有实现的组合，Derived 可接过已受控、同一几何同一本性的材料实体句柄，现场身份与材料量保持连续。 |
| Relations | 两端点、单向通道、本性或以太依据、现场有效条件。容量随配方规模和世界系数确定。寄托供给只沿绑定到实际储备与目标的关系支付。 |
| Processes | entry 与有身份的局部过程。每个过程分别有 enter、active、on、exit，可有有界 repeat 与汇合条件。 |
| Contracts | 每段绑定控制者、专注、移动承诺、实际付款端、最长时长、可选的归一化蓄力目标。过程转换负责交接，未交接的主动作用随退出关闭。 |
| Expression | 模块化轨道，随进入、持续、实际命中或退出更新。绑定真实进度、实体几何或实际事件。表现层只读，世界裁决独立。 |

[统一 Draft 2020-12 Schema](../../game/data/magic_v0_3/magic_dsl_v0_3.schema.json) 的根验证配方。`$defs` 另提供 CompilationInput、CompilationOutput、TrainingRecord、Scene 等边界类型。操作签名、可用本性和模块词汇由[注册表](../../game/data/magic_v0_3/registry.json)生成。更新登记后运行 `python -m tools.magic_dsl_v0_3.schema` 重建可供外部工具直接使用的 Schema。

## 空间、实际作用与查询

空间分为参照、几何、分布、连通和多主体组合。有限载体为 Body、PathGraph、SurfacePatch、Region。位置与方向可在施法开始、主体建立或每次读取时绑定。作用范围由几何、分布、遮挡、目标范围及有效通道决定。现场枚举有上限。路径与曲面可作为骨架，几何接触须另有材料边或传力依据。表面接触与视线在离线场景中由观察值给出。表现可越过实体轮廓，保持危险范围的可读性。

| 操作 | 机器签名与实际意义 |
|---|---|
| Establish / Withdraw | 在 enter 唯一建立局部句柄，在 exit 撤去自己拥有的作用；已发生的相变、运动与热量保留。 |
| Transfer | 将付款端实际可支用部分转入本次储备，进度限制在 0–1。 |
| Drive | 按局部通道施加有限冲量、加速度、热、照度、透过率或电荷。登记决定目标类型、作用时机及参数。 |
| Constrain | 以有限总承载响应观察到的接触；总负荷超过能力后该约束破裂。 |
| Transform | 可对一个质量在预算内的材料实体原位转固，也可逐段凝固。传播从绑定起点沿有效材料边推进，具有速度、跳数、距离上限、衰减和缺起点处理。 |
| Couple | 以实际扰动为输入，把信号交付到已绑定的接收端。 |

时间或空间上的分布（Profile）和向其他位置传递（Propagation）各有职责。首批封闭形式包括恒定持续、蓄积、一次交付、定次脉动、均匀或线性空间衰减，以及实时材料传播与有限导电通路。配方只可使用登记的作用签名。世界本体、执行载体、合法能力及已获实机验证的能力分别维护其判断依据。

## 过程、所有权和事件顺序

enter 一次，active 按实际支付的时间积分，exit 一次。on 的条件为 always、reserve_ready 或 reserve_low，事件取自释放、中断、超时、接触、信号、进入就绪。目标数组允许同时启动多个后继；all 等待各前置的实际通知，any 接受互斥入口。局部 repeat 声明间隔与次数，顶层过程图保持无环。契约的时限与支付均有限。状态组合分析拒绝不可达汇合、并行专注冲突、重复激活和重复句柄。

同一时刻先结算此前持续生效的区间，现场断边、断供或方向变化影响之后的提交。强制打断优先于松手，时限届满优先于该时刻新交付或重复。一个句柄同一时刻只有一个所有者，转交关系须同时保有其实体端点；进入汇合前由调度器暂存。撤去作用会结清本地责任，已经作用到世界中的后果由共享规律继续结算。离线配置支持单次施法的共享储备和一次按储备交付的冲量；多主体、多局部过程和自主寄托仍可组合。

## 规模、计费与硬顶

模型指定形状、物理尺度、时限、规模档与释放比例；精确蓝耗和总交付量由[版本化计费表](../../game/data/magic_v0_3/tariff.json)计算。当前系数是离线标尺。验收比较同来源同现场的差异，不能用于判断游戏平衡或物理精度。

- 空间工作量按载体系数、延伸尺度、锥角或拓扑细节计入。规模档乘以空间工作量因子。建立成本由基础、空间、关系与可能提交的一次性工作组成，有界重复按次数计；互斥路径也按保守上界报价。
- 每个过程有确定的每秒供给率；总费率展示上界。普通持续作用只按实际有效时间支取。蓄积最多支取到本次容量，储备比例等于实际入账量除以满额；持咒超出满额保持上限。
- 满额容量由蓄积速率乘满蓄时长得到。满额冲量由规模、几何与蓄积时长确定，实际冲量按实付储备比例折算，交付后消耗该储备。合格目标按声明的权重共同分配，遮挡、距离与锥角参与筛选。打断和未达阈值的释放会丢弃未交付储备。本离线标尺选择耗散策略。
- 身份、单位、类型、局部依据、形状与执行能力先校验，再查资源和空间硬顶。每术最多 8 个主体、12 个关系、8 个过程、4 个入口、16 个动态体、16 个路径节点、24 条边、64 个表面单元、3 个发光轨道及 30 秒时长。全局场景物理与帧耗由实际引擎测量。

## 演出与可复现入口

注册表提供 12 个视觉原型、8 种动态、8 个声音、3 个姿态及 1 个镜头模块，可按轨道组合。蓄力音和气流可绑定实际进度，释放波前可绑定几何，冲击强调可等待真实交付。离线推演输出触发轨迹；已登记的演出指令仍需要 Godot 资产兑现。

在根目录执行下列命令。CLI 子命令还包括 price、validate、input、accept、trial 和 record。校验失败给出非零退出码及 JSON 诊断。

```sh
D=game/data/magic_v0_3
uv run --isolated --with-requirements tools/magic_dsl_v0_3/requirements.txt python -m tools.magic_dsl_v0_3 read "$D/recipes/pressure_wind.json"
uv run --isolated --with-requirements tools/magic_dsl_v0_3/requirements.txt python -m tools.magic_dsl_v0_3 simulate "$D/recipes/pressure_wind.json" "$D/fixtures/wind.json"
uv run --isolated --with-requirements tools/magic_dsl_v0_3/requirements.txt python -m tools.magic_dsl_v0_3 accept "$D/fixtures/altar_input.json" "$D/fixtures/altar_output.json"
```
