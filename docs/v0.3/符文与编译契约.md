# 20 枚符文与编译契约 v0.3

玩家表达意向，模型在构筑期结合世界知识补全现象，确定性程序负责可形式化的检查、计费与执行。模型对法术的文字描述供审阅；最终法坛读解从获准的配方反向生成。

## 词库与开放波次

| 世界概念（11） | 组织与意向（9） |
|---|---|
| 土、水、气、火、光、电、重力、空、时、生、以太 | 聚、散、引、联、分、逆、藏、应、守 |

「聚」可以指物质结合，也可指在时间上积蓄作用。「分」可以指分开结构、抽离性质或切断联系。每枚词的语义提示保存在[注册表](../../game/data/magic_v0_3/registry.json)。冰、雾、凝固、回旋、焊接等仍可用于模型知识与实际配方。历史资料供语义参考，玩家只操作新词库。

完整盘子为 20 枚。离线法坛候选先接纳其中 18 枚，具体配方还受玩家已知符文和本次能力子集限制。「空」先用于参照、有限区域和内外；高阶空间通达延后。「时」「生」待局部演化与活体通道具有足够的实机世界响应再开放。18 是试构选择，实机开放名单需通过相应世界交互验收。「时＋逆」若明确要求改写历史，世界公理已排除该结果；合理但尚无后端的现象应报告能力缺口。

## 玩家提供的结构

构筑图中的节点有局部身份，同一字可多次使用。**共同组织**把多个成员放在同一意义整体，**局部关联**按成员次序由首项指向其余项，**发生接续**显式规定成员的因果先后。连接自身也有 ID，可作为另一组的成员，允许嵌套、分支及共享，依赖须有界。普通连接没有默认时间意义。候选配方用各符文贡献的过程引用证明显式接续。

施法情境描述对己、瞄准或对世界，以及即时、蓄力或留存。语义锚点指向具体符文或局部组，保存玩家可读的意义及可机检的世界机制。例如锚定「守」为承担外物负荷，模型仍决定形态、跟随方式和过载表现。候选中的相应符文贡献须指向实际兑现该作用的过程或对象。

## 法坛单次生成

1. `CompilationInput` 提供图、可选 SemanticAnchors、CastingContext、PlayerKnowledge、世界与 DSL 版本、受支持能力子集和艺术风格。开始推理前先查图、开放词与版本。
2. 模型一次返回 `CompilationOutput`，含完整 MagicDSL、Interpretation、逐枚 RuneContributions，以及零到两个备选锚点。备选须有当前支持、与默认机制可区分的真实作用。首轮只生成一份完整配方。同一机制也可用实际交付时机、控制者或供给来源区分用途；名称与颜色不会产生新锚点。
3. 确定性程序核对机器语法、能力、锚点局部证据、过程责任及预算。法坛展示由真实配方生成的空间、目标、供给、发生与退场条件。用户主动选择改锚后，保留原图及其余锚点，定向再生成一次。
4. 正常路径一次模型调用即结束。有明确校验错误时可启用一次带定位诊断的修正；再次失败就返回诊断。确认后保存版本化配方及规则版本；重复施放直接读取它。离线 API 接收生成函数，可用事先保存的模型响应复核这个流程。[法坛接口](../../tools/magic_dsl_v0_3/altar.py) · [完整输入和响应](../../game/data/magic_v0_3/fixtures)

世界许可、工程支持和玩家意向是独立问题。结构化约束解码可以限定模块名，Schema 通过也可能给出不贴切的魔法。封闭能力证据用于能机检的语义子集；组合是否自然、是否尊重叙事目的，仍需设计者或玩家判断。

## SFT、RL 与匹配率

统一 Schema 的 `TrainingRecord` 保留原输入、原始候选（含失败样本）、定位诊断、修正结果、版本、按现场事件采集的观测、事前预期与人类偏好。首选用受审配方教构思和改错；再分别评价合法率、资源守恒、世界响应、锚点兑现及偏好。离线模拟观测须与未来实机观测标明出处。训练时区分默认接受与主动改锚，两种样本可提供不同反馈。

80%–90% 是默认解释命中事前预期的目标。先记录玩家期待的主要作用，再给出默认配方和实际读解，分开统计首次命中、改锚后命中及能力缺口。意外发现主要来自未限定的组织和跨场景用途。模型实测、真人匹配率及本地推理延迟均待专项验证。
