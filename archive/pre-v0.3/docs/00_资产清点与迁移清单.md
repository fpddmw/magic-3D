## 三、明确退役的旧仓库内容（及退役原因）

以下内容永久封存于旧仓库 `../city-fates`（与 `fpddmw/citi-fates`），**本仓库严禁复活或重新引入**：

1. **`engine/`（约 18,050 行 C++20 / Vulkan 1.3 / HLSL 工程）与 `engine/content/`（2D 像素图集、构造 JSON 与诊断场景）**：
   - 退役原因：试图从零构建覆盖七组材料、FP64 切割单元 VOF/PLIC/FCT 流体、刚体双向耦合与动态像素合成的通用科学计算平台。工程极度脆弱且耗时巨大（一块刚体旋转 `1.78e-19` 弧度即遭边界拒绝），且与“厚重浪漫、大道至简的 3D 魔法表现”南辕北辙。
2. **`src/`、`include/`、`assets/`、`tests/`（约 4,306 行旧 2D 横版三术可玩原型）**：
   - 退役原因：早期 2D 横版实验代码，已退出当前 3D 架构。
3. **旧工程规格文档**：
   - 包括 `docs/工程/引擎实施计划.md`（1,511 行）、`游戏专用引擎_目标与设计.md`、`世界材料、结构与场景改造.md`、`魔法现象与连续演出.md`、`内容制作、调试与质量判断.md`、`语义理解与魔法生成.md`、`执行任务_K4固定网格压力支撑.md`、`docs/参考/pixel-magic-gallery/`。
   - 退役原因：整套文档均以“2D 像素＋自研 GPU 物理＋七组细分材质＋K1–K4 里程碑＋Devin 切分单”为核心假设，继续保留只会严重误导新会话的架构判断。
4. **旧构建与 Windows 批处理环境**：
   - `CMakeLists.txt`、`CMakePresets.json`、`THIRD_PARTY.md`、`cmake/`、`scripts/`、`build/` 及根目录 7 个 `.cmd` 启动脚本。
   - 退役原因：全面转向 Godot 4.x 原生跨平台工程（macOS Apple M6 Metal 开发 + Windows Vulkan 目标分发）。
